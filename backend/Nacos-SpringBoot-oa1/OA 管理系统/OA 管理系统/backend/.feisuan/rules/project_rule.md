### 1.2 目录结构
当前项目为Maven微服务聚合工程，现有目录结构如下：
```
backend
├── pom.xml                # 父工程POM，统一管理依赖版本与构建配置
└── gateway                # 网关子模块
    └── src
        └── main
            ├── java
            │   └── com
            │       └── oa
            │           └── gateway
            │               └── config    # 网关配置类目录（跨域、路由、过滤器等配置）
            └── resources
                ├── application.yml       # 网关核心运行配置
                └── bootstrap.yml         # Nacos配置拉取配置（使用配置中心时需添加）
```
> 后续新增业务子模块（如`oa-emp-service`员工服务、`oa-admin-service`管理员服务）需放在`backend`根目录下，遵循统一的`src/main/java`、`src/main/resources`目录结构。

## 三、分层架构规范
| 层级          | 职责说明                         | 开发约束与注意事项                                               |
|---------------|----------------------------------|----------------------------------------------------------------|
| **Controller** | 处理HTTP请求与响应，定义API接口 | 不得直接访问数据层，必须通过Service层调用；统一返回封装后的响应结果；接口路径符合RESTful规范，统一前缀为`/api/v1/{业务模块名}/` |
| **Service**    | 实现业务逻辑、事务管理与数据校验   | 必须通过Mapper层访问数据库；返回DTO/VO而非Entity（除非必要）；接口与实现分离，实现类放在`impl`子包中 |
| **Mapper**    | 数据库访问与持久化操作             | 继承`BaseMapper`；SQL语句统一写在`resources/mapper`目录下的XML文件中；使用`@Param`注解避免参数歧义；禁止在Mapper中编写业务逻辑；使用关联查询、懒加载等方式避免N+1查询问题 |
| **DO（Entity）** | 映射数据库表结构                   | 不得直接返回给前端，需转换为VO/DTO；统一放在`entity/do`包下，命名为`xxxDO` |
| **DTO** | 数据传输对象，用于层与层之间的参数传递 | 用于Controller接收请求参数、Service层内部参数传递，命名为`xxxDTO` |
| **VO** | 视图对象，用于返回给前端的数据封装 | 根据前端需求组装数据，隐藏敏感字段，命名为`xxxVO` |
| **Query** | 查询参数封装对象 | 用于复杂查询、分页查询的参数传递，命名为`xxxQuery` |

### 3.1 接口与实现分离
- 所有业务接口（Service、Feign接口等）需定义在对应包下，具体实现类放在同包下的`impl`子包中。
- Mapper接口统一放在`mapper`包下。

## 四、微服务与网关规范
### 4.1 Nacos规范
- 服务注册与发现、配置中心统一使用Nacos，服务命名遵循`oa-{业务模块名}-service`格式（如员工服务为`oa-emp-service`、管理员服务为`oa-admin-service`），与网关路由id保持一致。
- Nacos配置统一使用`public`命名空间、`DEFAULT_GROUP`分组，配置文件后缀为`yml`。
- 敏感配置（如数据库密码、Nacos密钥）需在Nacos控制台加密存储，禁止明文写在配置文件中。

### 4.2 网关规范
- 所有外部请求必须经过网关转发，禁止业务服务直接暴露公网端口。
- 网关已配置全局跨域规则，业务服务无需重复配置跨域，如有特殊跨域需求需在网关层统一配置。
- 路由规则统一在网关的`application.yml`中配置，路径前缀统一为`/api/v1/{业务模块名}/`，路由id与服务名保持一致。
- 现有AI客服服务为Spring Boot 3.x异构技术栈，暂不注册Nacos，网关采用直连`http://localhost:8083`方式访问，路由路径为`/api/v1/ai/**`。
- 网关层统一做权限校验、限流、日志记录等通用逻辑，避免重复代码。

## 五、安全与性能规范
### 5.1 输入校验
- 使用`@Valid`与JSR-303校验注解（如`@NotBlank`、`@Size`等），校验注解位于`jakarta.validation.constraints.*`包下。
- 禁止手动拼接SQL字符串，MyBatis参数传递优先使用`#{}`，动态拼接场景（如排序字段）使用`${}`时需对参数做转义处理，防止SQL注入攻击。
- 接口入参需做非空、格式、范围校验，禁止非法参数进入业务逻辑。

### 5.2 事务管理
- `@Transactional`注解仅用于**Service层**方法，禁止在Controller、Mapper层使用。
- 避免在循环中频繁提交事务，大事务需拆分，提升性能。

### 5.3 性能优化
- 数据库查询避免全表扫描，复杂查询需加索引。
- 热点数据优先使用Redis缓存，缓存key统一采用`oa:{业务模块}:{唯一标识}`格式（如员工缓存key为`oa:emp:{员工id}`），需设置过期时间，避免缓存穿透、击穿、雪崩。
- 分页查询统一使用PageHelper插件，禁止手动拼接分页SQL。
- 接口响应时间超过500ms的需优化，避免慢接口。

## 六、代码风格规范
### 6.1 命名规范
| 类型       | 命名方式             | 示例                  |
|------------|----------------------|-----------------------|
| 类名       | UpperCamelCase       | `UserServiceImpl`     |
| 方法/变量  | lowerCamelCase       | `saveUser()`          |
| 常量       | UPPER_SNAKE_CASE     | `MAX_LOGIN_ATTEMPTS`  |

### 6.2 类型命名规范（阿里巴巴风格）
| 后缀 | 用途说明                     | 示例         |
|------|------------------------------|--------------|
| DTO  | 数据传输对象                 | `UserDTO`    |
| DO   | 数据库实体对象               | `UserDO`     |
| BO   | 业务逻辑封装对象             | `UserBO`     |
| VO   | 视图展示对象                 | `UserVO`     |
| Query| 查询参数封装对象             | `UserQuery`  |

### 6.3 实体类简化工具
使用Lombok注解替代手动编写getter/setter/构造方法，统一使用`@Data`、`@NoArgsConstructor`、`@AllArgsConstructor`，需要链式构造时可添加`@Builder`注解；禁止使用`@Accessors(chain = true)`导致链式调用可读性下降。

## 七、扩展性与日志规范
### 7.1 接口优先原则
所有业务逻辑通过接口定义，具体实现放在`impl`子包中，方便后续扩展与替换实现。

### 7.2 日志规范
- 使用`@Slf4j`注解代替`System.out.println`，禁止在代码中打印敏感信息（如用户密码、身份证号）。
- 日志级别规范：`error`用于记录异常错误、`warn`用于记录警告信息、`info`用于记录关键操作、`debug`用于记录调试信息（仅开发环境开启）。
- 日志格式需包含操作时间、线程名、日志级别、类名、日志内容，方便排查问题。

## 八、编码原则总结
| 原则       | 说明                                       |
|------------|--------------------------------------------|
| **SOLID**  | 高内聚、低耦合，增强可维护性与可扩展性     |
| **DRY**    | 避免重复代码，提高复用性                   |
| **KISS**   | 保持代码简洁易懂                           |
| **YAGNI**  | 不实现当前不需要的功能                     |
| **OWASP**  | 防范常见安全漏洞，如SQL注入、XSS等         |
